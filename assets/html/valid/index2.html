Guia Rápido de Git

Conceitos essenciais, comandos práticos e um fluxo de trabalho recomendado — tudo numa única página.

O que é o Git?

Git é um sistema de controlo de versões distribuído criado por Linus Torvalds em 2005. Permite guardar o histórico do código, trabalhar em múltiplas branches, e colaborar sem perder rastreabilidade.

Principais vantagens: histórico eficiente, merges poderosos, ramificação leve e modelo distribuído.

Conceitos-chave

  • Repositório (repo): diretório com um histórico de versões (local ou remoto).
  • Commit: captura do estado do projeto com uma mensagem e autor.
  • Branch: linha independente de desenvolvimento (ex: main, feature/x).
  • Merge: integração de alterações entre branches.
  • Staging area (index): lugar entre arquivos modificados e o commit onde escolhes o que incluir.
  • Remote: repositório remoto (ex: GitHub, GitLab).

Comandos essenciais

Exemplos rápidos para começar:

git init                # criar repo local
git clone          # clonar um repo remoto
git status              # ver estado do repo
git add           # adicionar ao index (staging)
git commit -m "msg"    # criar commit
git branch              # listar branches
git checkout -b nome    # criar e mudar para branch
git pull                # buscar + integrar do remoto
git push                # enviar commits para remoto
git merge main          # merge da branch main

Fluxo de trabalho recomendado (feature branch)

  1. Partir de main atualizado: git checkout main && git pull
  2. Criar branch de trabalho: git checkout -b feature/descricao
  3. Trabalhar localmente, fazer commits pequenos e significativos.
  4. Manter a branch sincronizada: git fetch && git rebase origin/main (ou git merge se preferir).
  5. Abrir Pull Request / Merge Request para revisão e integração.
Por que rebase?

O rebase reescreve o histórico aplicando os seus commits no topo do último main, gerando um histórico linear mais fácil de ler. Use rebase em branches locais antes do PR; evite rebase em branches públicas.

Resolução de conflitos

Conflitos surgem quando duas alterações incompatíveis ocorrem no mesmo trecho de código. O fluxo genérico para resolver:

  1. Fazer git pull ou git rebase e observar o conflito.
  2. Editar os ficheiros conflituosos — Git marca as divisões com <<<<<<< e >>>>>>>.
  3. Adicionar os ficheiros resolvidos (git add) e concluir (git rebase --continue ou git commit).
<<<<<<< HEAD
versao local
=======
versao remota
>>>>>>> feature/x

Bons hábitos

  • Commits pequenos e com mensagens claras.
  • Use .gitignore para evitar ficheiros temporários no repo.
  • Reveja pull requests antes de integrar.
  • Proteja a branch main (políticas de merge, CI obrigatório).

Exemplo prático

Um pequeno fluxo de exemplo:

# criar repo e submeter ao GitHub
mkdir projeto && cd projeto
git init
echo "# Projeto" > README.md
git add README.md
git commit -m "feat: adicionar README"
# criar repo remoto no GitHub e adicionar remote
git remote add origin git@github.com:seuuser/projeto.git
git branch -M main
git push -u origin main
